Improving Handoff
with Figma’s dev mode

Integrating Figma's dev mode into the shared workflow between Design and Development flagged inconsistencies with the way we managed design handoff.

Cross team Collaboration

As part of an initiative to strengthen the design-to-dev handoff, I introduced key Figma Dev Mode features to the development team:

  1. Compare – allows tracking of Screen version history as the handoff finalises.
  2. Component playground – allows preview of all component variants
  3. VS Code plugin – to help developers access design tokens and components directly from code

These tools addressed specific issues raised in a joint retrospective and over a period of time became more widely used.

Compare Feature

From a developer’s perspective, Figma’s Dev Mode Compare is a really useful feature during sprint handoffs. It clearly shows what’s changed between design updates and syncs, which makes it easier to focus on just the updates instead of rechecking the entire file. This helps reduce confusion, speeds up implementation, and ensures you’re always building from the most accurate, up-to-date designs.

Component Playground

Figma’s Dev Mode Component Playground is just as valuable—it lets you interact with components directly in the file to test different variants, states, and content. As a developer, this gives you a clear understanding of how components are intended to behave before writing any code. It makes translating designs into code smoother, reduces guesswork, and helps ensure accuracy from the start.

Design System Improvements

Understanding these tools also gave me a better understanding of how dev mode is much more than just inspection of elements. Naming conventions and providing refine components & tokens can really improve the user experience of dev mode for your team mates.

  • Providing all screen UI in components allows compare feature to provide all change history.
  • Refining component variant names reduces redundancy so component playground is more intuitive.
  • Optimising variables and tokens so modes can be easily toggled in component playground.

Small Win

Personally I found the process rewarding as I learnt some valuable lessons from an aspect of work which can be easily overlooked. It also provided me a real time example of UX craft, refining how content within a system can benefit end users, aka our devs.
